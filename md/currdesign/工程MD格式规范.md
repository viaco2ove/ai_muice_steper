# 歌曲工程 MD 格式规范

本文档定义「歌曲工程 MD」的统一格式，作为整个项目的**唯一真相源**。它聚合和弦、歌词、多轨道、旋律、附件等半成品信息，并承载迭代日志与诊断结果。所有生成技能（ai_chords_master / muse-lyrics-gen / audio_chord_recognizer 等）的产物都映射进这个格式；song_engineer 技能基于它做诊断与持续优化。

设计原则与哼唱设计.md 一致：**人类可读、全平台兼容、支持 Git 版本管理、解析成本极低**。本规范是 workbuddy 路线（第一阶段）与完整前后端工作台（第二阶段）共享的契约，先定格式、再上可视化。

---

## 一、设计原则

1. **内嵌优先，引用为辅**：核心创作信息（和弦骨架、段落结构、歌词、多轨规划、诊断）直接写在工程 MD 内；大体积二进制产物（wav/mid/mp3）用相对路径引用。
2. **字段单一来源**：BPM、调号、Capo 等基础属性只在「元信息」或「基础信息」写一处，其他区块写「见元信息」或省略，杜绝现有产物里 BPM/Capo 在多处各写一遍且可能矛盾的问题。
3. **和弦级不碰音符级**：MD 只保留和弦级与段落级信息；逐音符的简谱/五线谱导出为 MIDI 附件，MD 内引用。符合「先做和弦级，不碰音符级」的定位。
4. **时间维度双轨**：和弦既可「按小节」（创作/编曲视角，来自 ai_chords_master），也可「按秒」（扒谱/音频分析视角，来自 audio_chord_recognizer）。两者都保留，用不同子区块区分。
5. **迭代可回溯**：工程日志与诊断区块记录每次变更，形成可回溯的迭代链，支撑「持续优化和编辑」。

## 三、区块职责与字段说明

### 1. 元信息
全工程的字段单一来源。`状态` 字段标识工程成熟度，是诊断的输入之一。

### 2. 基础信息
乐器演奏向属性，服务于"怎么弹"。`实际音高 = 编配调 + Capo 半音数`，应自动推算并校验一致性。

### 3. 段落结构
表格 + 单行「结构串」两种形式并存：表格供 AI 结构化解析，结构串供人快速阅读。小节数总和应与各段对齐。

### 4. 多轨道规划（核心新增）
本阶段多轨 = **文本级乐器分轨规划**，不处理真实音频分轨文件。每轨记状态，让"半成品"的完成度可视化。诊断时重点检查：风格禁用的乐器（如沙发小曲禁鼓组）不应出现在轨道里，或状态应标"不需要"。

### 5. 和弦详情
三个子区块对应三个来源/视角：
- **骨架 + 丰富化展开 + 把位速查**：来自 ai_chords_master（按小节，创作视角）
- **和弦时间线**：来自 audio_chord_recognizer（按秒，扒谱视角）

两者并存不冲突：前者是"打算怎么弹"，后者是"实际音频里是什么"。诊断时可对照两者差异。

### 6. 歌词
保留现有 lyrics.md 的全部格式（【全局设定】+ 结构标签 + 编曲说明括号 + 韵律设计表），可直接内嵌或整体引用。

### 7. 附件与引用
所有二进制与大体积产物用相对路径。路径基准 = 工程文件所在目录（`workspace/project/{歌名}/`）。

### 8. 工程日志（核心新增）
每次变更追加一行，记录动作类型（初始化/诊断/优化/人工编辑）、变更摘要、来源（哪个技能或人工）。这是迭代闭环的回溯依据，对应 Git diff 的人类可读摘要。

### 9. 诊断与优化方向（核心新增）
song_engineer 的产出区。三个子区块：现状诊断（按诊断维度）、优化建议（带优先级）、知识点（关联 kb_repo）。每次重新诊断覆盖本区块，旧的诊断进工程日志。

## 五、解析与序列化约定

- **解析**：读 MD → 提取各 `##` 标题为区块 → 表格转结构化数组 → 代码块标记和弦 → 输出 JSON。
- **序列化**：JSON → 按本模板拼装回 MD 字符串 → 写入文件。
- **代码块标记**：和弦类内容用纯文本代码块（```无语言标识），便于提取。
- **表格**：标准 Markdown 表格，列名固定（见模板），缺列留空。
- **路径**：统一相对路径，基准为工程文件目录。

## 六、与现有 project.md 雏形的关系

`workspace/project/走在/project.md` 是本格式的自发雏形，已包含风格定位/基础信息/和弦骨架/旋律特征/工程资源链接。本规范在其基础上：
1. **统一字段名**：消除"编配调"vs"弹法"等不一致。
2. **新增三块**：多轨道规划、工程日志、诊断与优化方向。
3. **消除重复**：BPM/Capo 等只在元信息/基础信息写一处。
4. **规范区块顺序与表格列名**：保证解析稳定。

song_engineer 的「初始化模式」负责把现有 project.md 及散件升级/聚合为本规范格式。
