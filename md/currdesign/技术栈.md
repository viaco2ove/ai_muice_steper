### 一、整体技术栈选型（个体开发者轻量化优先）
整体遵循「**开发效率优先、维护成本最低、能力可插拔**」的原则，贴合你「轻量化AI音乐助手、逐个落地小工具」的定位，避免重型架构。核心分为 4 层，全部支持本地部署，仅 LLM 调用按需付费。

| 层级 | 技术选型 | 选型核心理由 |
| :--- | :--- | :--- |
| 前端（交互层） | React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui | 组件生态成熟，开发速度快；MD编辑器、音频录制、波形可视化均有现成高质量库，适合快速搭出左右分栏工作台 |
| 业务后端 | Python + FastAPI | 和AI服务同语言，无需跨语言维护；自动生成API文档，性能足够；个体开发者单语言栈维护成本最低 |
| AI能力层 | Python + Librosa + CREPE + 可插拔和弦模型 | 旋律提取、和弦生成都在CPU即可跑，无额外算力成本；模型可替换，初期用规则算法快速落地，后期无缝替换深度学习模型 |
| 数据/存储层 | SQLite + 本地文件系统 | 零配置，无需搭数据库服务；工程本体以MD文件存在磁盘，天然支持Git版本管理，符合「简单兼容」的需求 |
| LLM对接 | 直接调用大模型API（豆包/通义千问等） | 避免本地部署大模型，成本可控；利用函数调用能力实现Agent工具编排 |
| 部署 | Docker Compose 一键编排 | 本地开发、线上部署一套配置搞定，单台轻量服务器即可跑全量服务 |

### 二、整体架构设计
采用「前后端分离 + AI能力微服务化」的分层架构，核心是**业务与AI解耦**，后续新增音乐小工具只需要在AI层加模块，不用动主业务。

```
┌─────────────────────────────────────────────────────────┐
│                     前端工作台                          │
│  左侧聊天Agent  │  右侧MD工作空间（编辑+预览）         │
│  录音/上传音频  │  和弦可视化、段落结构、分轨规划      │
└───────────────────────────┬─────────────────────────────┘
                            │ HTTP/WebSocket
┌───────────────────────────▼─────────────────────────────┐
│                    业务后端服务                         │
│  会话管理  │  工程文件CRUD  │  Agent编排调度  │  工具路由 │
└───────────┬───────────────┬───────────────┬─────────────┘
            │               │               │
┌───────────▼───────┬───────▼───────┬───────▼─────────────┐
│   旋律分析模块    │  和弦生成模块 │  MIDI导出模块       │  ← AI能力微服务
│  (CREPE+Librosa) │ (可插拔模型)  │  (mido/pretty_midi) │
└───────────────────┴───────────────┴─────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│                    存储层                                │
│  SQLite(元数据)  │  MD工程文件  │  音频/MIDI附件        │
└─────────────────────────────────────────────────────────┘
```

**核心设计原则**：
1.  MD工程文件是唯一真相源：所有业务数据都落地到MD，前端渲染、AI分析都基于MD解析，不搞冗余数据库存储
2.  AI能力可插拔：所有音乐工具都封装成独立的HTTP接口，后端只负责调用，后续加新工具（比如歌词生成、风格推荐）只需要新增接口
3.  Agent轻量实现：不搞复杂的Agent框架，直接用大模型的函数调用能力，后端做简单的工具执行和结果拼装

### 四、核心模块设计说明
#### 1. MD工程文件解析层
这是整个项目的核心纽带，前后端共用一套解析规则，保证双向同步一致。
- **格式标准**：采用「YAML Frontmatter + Markdown 分节」的格式，和你之前定的模板完全对应
- **解析逻辑**：
  - 读取MD → 提取Frontmatter为基础信息 → 按标题拆分各个章节 → 解析和弦代码块为结构化数组 → 输出标准JSON
  - 修改后反向：JSON数据 → 按模板拼装回MD字符串 → 写入文件
- **位置**：`common/md-parser/` 目录，前后端各实现一份，保证格式完全对齐

#### 2. Agent 编排层（轻量实现，不引入重型框架）
- 核心靠大模型**函数调用**能力，把「旋律分析」「生成和弦」「导出MIDI」「搜索参考歌（OpenClaw）」等注册为工具
- 后端只做简单的：接收用户消息 → 传给LLM获取工具调用指令 → 执行对应工具 → 把结果回传给LLM → 返回最终回答
- 上下文里永久挂载当前工程的MD结构化数据，保证AI所有分析和建议都基于当前工程内容

#### 3. AI能力层的可插拔设计
- 所有音乐工具都遵循统一的输入输出接口规范
- 以和弦生成为例：初期可以先用「基于流行和声规则的简单算法」快速落地，后续想换成AutoHarmonizer深度学习模型，只需要替换实现类，接口完全不变
- 方便你逐个添加小工具，每加一个都是独立模块，不影响现有功能

### 五、MVP 落地优先级建议
按「先跑通核心链路，再逐步增强」的顺序开发，最快1-2周就能出可用版本：

1.  **第一阶段：核心闭环（1周）**
    - 前端：左右分栏基础布局、MD预览、音频上传
    - 后端：工程CRUD、MD解析、基础音频分析接口
    - AI：基础旋律提取 + 规则版和弦生成 + 简单段落规划
    - 产出：上传哼唱 → 自动生成带和弦的MD工程 → 右侧可预览编辑

2.  **第二阶段：Agent对话增强（1周）**
    - 接入LLM，实现聊天对话、旋律点评、创作建议
    - 实现函数调用，支持用自然语言指令修改和弦、调整结构
    - 双向同步：手动改MD后，对话上下文自动更新

3.  **第三阶段：工具扩展（持续迭代）**
    - 新增MIDI导出、歌词生成、风格推荐
    - 接入OpenClaw等第三方工具
    - 替换更精准的深度学习和弦模型
    - 新增Git版本管理、工程导出分享等功能
