# minimax muisc  一次性 vs 分轨多次
一次性 vs 分轨多次：策略分析

  两种模式对比
  
  ┌─────────────────┬────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │      维度       │        一次性生成(推荐 ⭐)         │                      分轨多次生成                      │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 每次请求产出    │ 1 首完整 mp3 (人声+吉他+和声+环境) │ 1 条音轨 wav (如单独吉他轨 / 单独人声轨)               │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ API 调用次数    │ 1 次                               │ 10+ 次 (每轨一次)                                      │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 免费版额度消耗  │ 低                                 │ 高(可能撞额度)                                         │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 人声/配器协调性 │ ✅ 模型内部一致,无相位/混音问题    │ ⚠️ 各轨时长/调性/BPM 难精准对齐,合成后人工混音工作量大 │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 可控性          │ 仅能控歌词+风格+标签               │ ✅ 每条轨音色/段落精细控制                             │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 音色一致性      │ ✅ 同一人声/同一种吉他在全曲       │ ⚠️ 不同请求可能换"歌手"或"吉他音色"                    │
  ├─────────────────┼────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ 适合场景        │ 歌词驱动的 Lo-Fi 沙发小曲          │ 复杂编曲(交响/电影配乐)                                │
  └─────────────────┴────────────────────────────────────┴────────────────────────────────────────────────────────┘

  Music-3.0-free 的实际限制

  看 .env default_minimax_muisc=Music-3.0-free —— 这是免费版，额度紧。结合本曲特点（沙发核、8 段、单吉他+人声+极淡环境），强烈推荐一次性生成：
  1. 免费版通常每天/每周有 N 次调用上限,分轨 10+ 次直接撞墙
  2. 本曲是沙发核,极简配器,模型一次性出完全够用
  3. 歌词已严格按 minimax 控制标签分段,模型内部段落对齐是它最擅长的事
  4. 分轨合成反而要你自己在 DAW 里做对齐/混音,工作量大 10 倍

  唯一适合分轨的情况

  如果你最终想要：
  - 自己控制每轨音量平衡 → 一次性生成后用 audacity 切干声分离(unmix AI 工具)
  - 替换某条轨(比如换个吉他音色) → 分轨生成,只重做那条
  - 现有 wav 的某些轨很糟糕 → 重做那些轨

  推荐策略(混合)

  一次性生成作为基底 + 2-3 次分轨替换差轨：

  第 1 次(必):一次性生成完整 mp3
     ↓
     听成品,评估哪条轨差(通常人声最差或吉他最干)
     ↓
  第 2-N 次(可选):单独重生成那些差轨
     - 用 minimax 的 instrumental-only 模型(纯音乐,无人声)
     - 或单独生成 vocal stem + instrumental stem
     ↓
     在 audacity 重新对齐合成

  我建议的下一步

  先做一次性生成：把 workspace/project/走在/song_engineer/prompt_for_online_generator.md 第三节的"完整歌词+控制标签"整段复制粘贴到 MiniMax Music 3 网页或 Muse AI 即可。

  如果出来的成品人声仍然不对或某轨不理想，再考虑分轨重生成。

# 官网文档
https://platform.minimaxi.com/docs/api-reference/music-generation

model
enum<string>必填
使用的模型名称。可选值：

music-3.0（推荐）：文本生成音乐，仅限 Token Plan 用户和付费用户使用，RPM 为 120
music-2.6：上一代文本生成音乐模型，仅限 Token Plan 用户和付费用户使用，RPM 为 120
music-cover：基于参考音频生成翻唱版本，仅限 Token Plan 用户和付费用户使用，RPM 为 120
music-3.0-free：music-3.0 的限免版本，所有用户可通过 API Key 使用，RPM 为 3
music-2.6-free：music-2.6 的限免版本，所有用户可通过 API Key 使用，RPM 为 3
music-cover-free：music-cover 的限免版本，所有用户可通过 API Key 使用，RPM 为 3
可用选项: music-3.0, music-2.6, music-cover, music-3.0-free, music-2.6-free, music-cover-free
