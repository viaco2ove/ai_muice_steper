# 分类
- llm 生成文本类乐谱（强模型和专类模型）
- 音频生成模型（Suno/Udio/MusicGen）

# 核心结论先讲清楚
1. **不是所有LLM都会写可编辑歌曲（MIDI/JSON乐谱）**
   通用大模型分三档：**完全不会、勉强能写、专业音乐LLM**；音频生成模型（Suno/MusicGen）只会出音频，原生不输出可编辑MIDI/JSON乐谱。
2. 只有两类模型能稳定输出**人类可读、可修改的JSON+结构化MIDI乐谱**：
   - 强通用LLM（GPT-4o、Claude 3.5/4、Gemini Advanced、DeepSeek V3）
   - 音乐垂直专用LLM（ChatMusician、MIDI-LLM、SongComposer、Mureka O1、ACE-Step）
3. 区分关键：
   - 只会写歌词/和弦文字 ≠ 会写可编辑乐谱JSON/MIDI；
   - 生成完整歌曲音频 ≠ 输出可编辑符号乐谱（音频不能逐音符修改）。

## 一、通用LLM：能力分层（能不能输出乐谱JSON/MIDI）
### 1）入门弱模型：几乎做不到（不会正经写歌乐谱）
代表：GPT-3.5普通版、免费Gemini、基础通义千问、普通Llama3 8B、豆包轻量版
局限：
- 只能写纯文字歌词、简单和弦序列文字；
- 你强制要求JSON/MIDI，输出大量乐理错误、音符错乱、格式残缺；
- 无法对齐歌词与旋律时值，多轨分轨JSON基本崩坏；
- 仅适合写词，**不适合生成可编辑乐谱**。

### 2）强通用旗舰LLM：稳定输出规范乐谱JSON、MIDI描述文本（推荐）
代表：GPT-4o / GPT-4o-mini、Claude 3.5 Sonnet / Claude 4、Gemini Advanced、DeepSeek-V3、通义千问Ultra、豆包专业版
能力（满足你「人类可编辑+LLM读写」需求）：
1. 支持强制JSON结构化输出（多轨：人声/鼓/贝斯/钢琴，包含音高、时长、BPM、歌词、和弦、颤音参数）；
2. 输出标准MIDI文本描述，可一键转`.mid`文件导入DAW/SynthV/ACE；
3. 懂乐理：调式、凯尔特Dorian、和弦转位、段落结构、人声咬字时值对齐；
4. 双向可编辑：
   - 人类改JSON字段（音符、歌词、歌手ID）丢回去，AI重新生成修正旋律；
   - AI生成初稿JSON，人用VS Code/DAW可视化修改；
5. 可控指定虚拟歌手参数（对接SynthV/ACE歌手ID写入JSON）。

短板：
需要精准提示词约束，不然偶尔出现和声错误；**无原生MIDI文件导出，只能输出文本JSON/MIDI代码**，需要脚本转实体MIDI。

### 3）音乐垂直专用LLM（最优，天生写乐谱，专业编曲向）
专门用百万级MIDI乐谱、带歌词对齐乐谱训练，**原生支持多轨JSON+标准MIDI**，乐理、旋律、人声匹配远强于通用LLM。
1. ChatMusician（Skywork 天工）
   开源免费，原生输出ABC乐谱、MIDI、结构化JSON，歌词旋律逐字对齐，支持分轨，本地可部署，适合自制管线。
2. MIDI-LLM（MIT学术模型）
   专为「文本→多轨MIDI+JSON」设计，输出标准化乐谱结构，完美适配DAW、SynthV歌手渲染管线。
3. SongComposer
   歌词+旋律联合生成专用LLM，输出带拼音、气声参数的人声JSON，对接虚拟歌手无适配成本。
4. Mureka O1 / ACE-Step（国产商用）
   内置海量中文歌手模型ID，生成JSON直接包含歌手音色参数、滑音/颤音曲线，导出后可直接丢进ACE Studio编辑人声。

## 二、音频生成模型（Suno/Udio/MusicGen）：不算能「写可编辑乐谱」
很多人混淆，这里明确区分：
1. 它们的强项：一键生成完整歌曲音频（带真人质感人声）；
2. 短板：
   - 原生不输出结构化MIDI/乐谱JSON；
   - 所谓导出MIDI是**音频反向转写**，音符错位、时值不准、丢失人声精细参数；
   - 无法逐音符人工编辑底层旋律，只能整体重生成段落；
3. 定位：快速听成品，不适合你要的「JSON/MIDI双向人工编辑管线」。

## 三、最简选型方案（匹配你的需求：人类可编辑JSON/MIDI + AI生成）
### 方案A：快速上手，不用本地部署（网页直接用）
Claude 3.5 Sonnet / GPT-4o
优势：提示词约束后稳定输出干净多轨乐谱JSON，人人能看懂，复制到VS Code即可修改。

### 方案B：本地离线、无API费用、音乐专业度拉满
ChatMusician + MIDI-LLM
优势：开源免费，原生乐谱输出，批量生成分轨，可嵌入你的脚本管线。

### 方案C：中文虚拟歌手工作流（SynthV/ACE）
Mureka O1 / ACE-Step
生成的JSON自带歌手标识、拼音、演唱参数，无需二次适配，直接导入人声编辑器精细调整。

## 四、补充关键规则
1. 不存在「所有LLM都会写规范乐谱」，弱通用模型完全达不到可编辑标准；
2. 区分两个概念：
   - 写歌（出音频）：Suno、MusicGen都行；
   - 写**可编辑乐谱（JSON/MIDI符号）**：只能选强通用旗舰LLM / 音乐专用LLM；
3. 闭环工作流（你要的人机双向编辑）：
   自然语言需求 → LLM输出多轨乐谱JSON → 人类文本修改JSON音符/歌词/歌手 → 回传给LLM重生成优化旋律 → 转MIDI送入AI歌手渲染干声。
