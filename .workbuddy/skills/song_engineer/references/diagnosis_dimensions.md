# 诊断维度细则

song_engineer 诊断模式的五维诊断标准。每维给出检查项、判定规则、严重级别与教学关联。

---

## 维度 1：完整性

检查工程MD各区块是否齐全、字段是否填写。

### 检查项

| 区块 | 必填 | 检查内容 |
|------|------|----------|
| 元信息 | 是 | 歌名/风格/BPM/调号/状态 是否填写 |
| 基础信息 | 条件 | 如有 Capo 则编配调/实际音高必填 |
| 段落结构 | 是 | 至少有结构串；有表格更佳；小节数总和应等于总时长推算 |
| 多轨道规划 | 是 | 是否建立？每轨是否有状态？（无轨道规划 = 半成品未结构化） |
| 和弦详情 | 是 | 是否有骨架？丰富化展开是否完成？ |
| 歌词 | 是 | 是否覆盖所有段落？【全局设定】是否齐全？ |
| 旋律特征 | 建议 | 音域/中心音是否记录 |
| 附件与引用 | 建议 | 哼唱音频/MIDI 是否引用 |
| 工程日志 | 是 | 是否有初始化记录 |
| 诊断与优化方向 | 诊断后 | 本区块由诊断模式生成 |

### 完整性评分

```
已填写必填区块数 / 必填区块总数 = 完整度百分比
渲染为 [▓▓▓▓░░░░] 进度条
```

### 严重级别

- 🔴 缺失核心区块（段落结构/和弦骨架/歌词）-> 高
- 🟡 缺失建议区块（多轨道/旋律特征/附件）-> 中
- 🟢 缺失可选区块（和弦时间线/韵律设计说明）-> 低

## 维度 2：一致性

检查同一字段在工程MD与引用产物间是否矛盾。这是"半成品分散"最容易出问题的地方。

### 检查项

| 字段 | 工程MD来源 | 对照来源 | 规则 |
|------|-----------|----------|------|
| BPM | 元信息 | lyrics【全局设定】/ 和弦方案 | 必须相等 |
| 调号 | 元信息 | lyrics【全局设定】/ 和弦方案 | 必须一致 |
| Capo | 基础信息 | 和弦方案 | 必须相等 |
| 编配调 | 基础信息 | 和弦方案 | 必须相等 |
| 实际音高 | 基础信息 | = 编配调 + Capo | 自动推算校验 |
| 总小节数 | 段落结构表 | 和弦方案的小节展开 | 必须相等 |
| 段落数 | 段落结构表 | 歌词结构标签数 | 应对应 |

### 判定与输出

```
✅ 一致：Capo=3 与编配调=C/实际音高=Eb 匹配
⚠️ 不一致：工程MD BPM=68，但 lyrics 全局设定 BPM=72
❌ 矛盾：段落结构表总小节数=36，和弦方案展开=40
```

不一致时优先信任和弦方案（最权威的音高来源），建议修正工程MD。

## 维度 3：段落-和弦-歌词三者对齐

检查三者的对应关系，这是"半成品"能否合成"成品"的关键。

### 检查项

1. **段落结构表 -> 和弦**：表中每个段落是否在骨架/丰富化中有对应和弦？
2. **段落结构表 -> 歌词**：表中每个段落是否在歌词中有对应标签？
3. **歌词 -> 段落结构**：歌词的每个标签是否在段落结构表中？（如歌词有 [Verse 3] 但表中只有主歌A/B/A'）
4. **小节数匹配**：段落声称 8 小节，和弦展开是否也是 8 小节？

### 对齐矩阵

输出一个三列对照表：

| 段落结构表 | 和弦骨架 | 歌词标签 |
|-----------|---------|---------|
| 前奏[4] | ✅ C7-Em7/B | ✅ [Intro] |
| 主歌A[8] | ✅ | ✅ [Verse 1] |
| 主歌B[8] | ✅ | ✅ [Verse 2] |
| 间奏[4] | ✅ | ✅ [Interlude] |
| 主歌A'[8] | ⚠️ 和弦未区分A' | ✅ [Verse 3] |
| 尾奏[4] | ✅ | ✅ [Outro] |

缺项标 ⚠️ 或 ❌。

## 维度 4：风格契合度

对照 `md/kb_repo/style/` 下对应风格规范检查。这是"教学"价值最高的维度。

### 沙发小曲（Sofa Tune）检查项

对照 `md/kb_repo/style/沙发小曲_Sofa_Tune.md`：

| 检查项 | 规则 | 判定 |
|--------|------|------|
| 鼓组 | 沙发核禁鼓组；沙发绽仅极弱 | 多轨道/歌词禁用项检查 |
| BPM | 60-75 | 元信息 BPM 校验 |
| 和弦进行 | 属七->转位小七的半音低音下行 | 和弦骨架检查 C7->Em7/B 结构 |
| 大横按 | 禁止 | 把位速查检查 |
| 增/减和弦 | 禁止（基础形态） | 和弦检查 |
| 爆发 | 禁止高潮爆发 | 歌词情绪检查 |
| 能量 | 被动放松->主动沉聚 | 旋律特征检查 |

### 爱尔兰民谣检查项

对照 `md/kb_repo/style/爱尔兰民谣.md`：
- 凯尔特调式（Dorian/Mixolydian）特征
- 配器（哨笛/小提琴/木吉他/宝思兰鼓）
- 意象（自然/流浪/神话）

### 通用风格检查

如工程MD风格在 kb_repo 无对应规范，则跳过风格契合度维度的具体检查，仅做通用音乐逻辑检查（如和弦功能走向是否合理、段落能量起伏是否合理）。

## 维度 5：优化空间

给出可操作的优化建议，每条带优先级与建议动作。

### 优化方向分类

| 方向 | 建议动作 | 调用技能 |
|------|---------|----------|
| 和弦丰富化 | 骨架展开/色彩和弦/转位 | ai_chords_master |
| 结构平衡 | 增减段落/调整小节数/能量曲线 | ai_chords_master |
| 歌词韵律 | 统一韵部/闭口开口音/韵脚位置 | muse-lyrics-gen |
| 歌词内容 | 段落补充/意象深化 | muse-lyrics-gen / muse_ai_master |
| 多轨完整性 | 补充缺失乐器/声部 | 直接编辑工程MD |
| 旋律走向 | 动机发展/情绪落点 | ai_chords_master |
| 扒谱校准 | 对照真实音频修正和弦 | audio_chord_recognizer |

### 优先级规则

- **[高]**：影响完整性或一致性的问题（缺核心区块、字段矛盾）
- **[中]**：影响对齐或风格契合度的问题（段落不对应、风格禁用项出现）
- **[低]**：锦上添花的优化（丰富化不够、韵律可更统一）

### 输出要求

每条建议必须：
1. 指出**具体问题位置**（哪个段落/哪轨/哪个字段）
2. 给出**建议动作**（不只是"可以优化"，而是"建议把 Verse 2 的韵部从 ei/ü/i 统一为 i/ü"）
3. 标注**可调用的技能**（让用户知道下一步找谁）
4. 关联**知识点**（引用 kb_repo 具体文档，做教学）

---

## 诊断执行顺序

1. 完整性（基础，决定能否诊断其他维度）
2. 一致性（字段层面的矛盾）
3. 对齐（结构层面的对应）
4. 风格契合度（内容层面的合规）
5. 优化空间（基于前四维的综合建议）

每维独立判定，最后汇总成「诊断与优化方向」区块写入工程MD。
