# track_melody_master — 多轨旋律设计器

## 解决什么问题

根据歌曲的节奏吉他骨架（08_节奏吉他），自动重新设计非主唱乐器轨道：
- **solo 吉他**（05_主/06_辅1/07_辅2）— 旋律线设计
- **和声**（09）— 人声和声编排
- **pad**（10）— 氛围铺底
- **泛音点缀**（12）— 空灵环境音

**核心理念**：节奏吉他密集时 solo 静默，节奏吉他留白时 solo 登场。

## 触发词

重新设计分轨、设计非主唱轨道、solo 编排、和声设计、pad 设计、根据节奏吉他设计、重新生成所有分轨

## 前置知识

### 数据文件结构

每个分轨由 **两个镜像文件** 组成，必须同步更新：

```
workspace/project/{歌名}/song_engineer/track/
├── {N}_{名称}.md   ← 设计文档（人读）
└── {N}_{名称}.json ← 音符数据（机读，musecore-cooperate 的输入）
```

**JSON 格式**（所有轨道通用）：
```json
{
  "schema": "track.{type}.v1",
  "track_id": N,
  "type": "乐器",
  "name": "轨道中文名",
  "instrument": "乐器描述",
  "role": "角色定位",
  "program": GM音色号,
  "status": "定稿",
  "notes": [
    {
      "note": "Eb4",           // 音名(可留空=用midi)
      "actual": "Eb4",         // 实际音高名
      "midi": 63,              // MIDI音符号
      "duration": "8分",       // 时值: 全/2分/4分/8分/16分/32分
      "beat_pos": "21.1.1",    // 位置: 小节.拍.子拍(从1开始)
      "dynamics": "p",         // 力度标记
      "velocity": 64,          // MIDI力度 1-127
      "finger": "i",           // 指法(吉他用)
      "technique": "击勾弦",   // 技法: 击勾弦/滑音/泛音/琶音/pad持续
      "chord": "Em7"           // 所属和弦(可为空)
    }
  ]
}
```

**beat_pos 格式**：`小节.拍.子拍` （三段都是 1-based）
- `21.1.1` = 第21小节第1拍第1子拍
- `21.3.2` = 第21小节第3拍第2子拍（8分音符后半拍）
- 4/4拍下每拍有4个子拍，子拍1~4对应：正拍/8分后半/16分第三/16分第四

**duration 映射**（在 68 BPM 下）：
| 时值 | ticks | 实际秒数 |
|------|-------|---------|
| 全 | 1920 | ~3.53s |
| 2分 | 960 | ~1.76s |
| 4分 | 480 | ~0.88s |
| 8分 | 240 | ~0.44s |
| 16分 | 120 | ~0.22s |
| 32分 | 60 | ~0.11s |

**dynamics → velocity 参考**：
ppp=30, pp=45, p=60, mp=75, mf=85, f=95, ff=105, fff=115

### 节奏吉他 (08) 的策略信号

| 段落 | 小节 | 节奏型 | 含义 |
|------|------|--------|------|
| Intro | 1-4 | 基础A (密集拍弦+四勾) | **solo 静默** |

## 设计工作流

### Step 1: 加载上下文

先读以下文件获取完整歌曲上下文：
1. `workspace/project/{歌名}/song_engineer/track/08_节奏吉他.md` — 和弦进行 + 段落表 + 节奏策略
2. `workspace/project/{歌名}/song_engineer/track/08_节奏吉他.json` — 实际的 beat_pos 分布（确认"留白"段落精确起止）
3. 各目标轨道的现有 `.md` + `.json` — 了解当前状态

### Step 2: 确定音域与角色（不同轨道不同策略）

| 轨道 | 音域 | 技法 | 力度 |
|------|------|------|------|
| 05_solo吉他主 | Eb3~Ab4 | 击勾弦/滑音 legato | mf→mp→p→pp |
| 06_solo吉他辅1 | G2~Eb4 | 琶音分解+击勾弦 | p~pp |
| 07_solo吉他辅2 | Gb2~Bb3 | 滑音 s + 推弦 | p~pp |
| 09_和声 | F3~C4 | 平行三度/六度 | pp~p (主唱的60~70%) |
| 10_氛围垫音pad | Eb2~Eb4 | 长音持续 | ppp (几乎感觉不到) |
| 12_泛音环境点缀 | Eb4~Bb5 | 12品泛音 | pp (偶发) |

### Step 3: 设计原则

#### 3.1 solo 轨道 (05/06/07)

**"谁说话"的优先级**：
1. **主唱** (02) 说话时 → solo 全部闭嘴或极弱
2. **节奏吉他基础A** (密集) → solo 静默或极简1-2音点缀（句尾弱桥接）
3. **节奏吉他基础B** (琶音留白) → solo 登场，乐句2-4小节，留1拍气口

**旋律原则**：
- 五声音阶：Eb F G Ab Bb（Eb调五声）
- 允许经过音 Db/E（布鲁斯色彩）
- 乐句内 legato（击勾弦连续），乐句间留 4分~2分 气口
- 每段 solo 有一个情绪高点（Ab4），然后回落
- 结尾长音（2分~全音符）收束

**05 vs 06 vs 07 的分工**：
- **05 主** = 旋律主线，最突出的那个声音。间奏+主歌A'+尾奏三段主solo
- **06 辅1** = 05 的呼应/补充。05 休息时接话，05 长音时做分解填充
- **07 辅2** = 色彩点缀。只在副歌段落闪现，布鲁斯滑音推弦，给和声添"脏色"

#### 3.2 和声轨道 (09)

- **基于主唱 (02) 旋律移位**（三度/六度平行）
- 副歌段高三度，主歌段低三度
- 不超 C4，不低于 F3
- 力度 = 主唱同位置 velocity 的 0.6~0.7
- 间奏、尾奏静默（不和声 solo 段）
- 歌词 char 字段与主唱一致

#### 3.3 氛围垫音 (10)

- 每个和弦用**根音 + 五音**双音长持续（2分~全音符）
- 力度 ppp（vel=25~35），不可感知但可察觉
- 和弦切换时滑音过渡（用 pitch bend 实现不现实，改在同音名上微调 1-2 半音）
- 从头到尾铺满

#### 3.4 泛音点缀 (12)

- 只在段落的**换气口**出现（前奏末、段落衔接处、尾奏）
- 取当前和弦的高音做 12 品自然泛音（+12 半音）
- 力度 pp，长音 2分~全音符 fade out
- 每段最多 2-3 个泛音
- 尾奏 49-52 连续 4 个泛音渐弱至无
- technique 字段：`"泛音"`

### Step 4: 重新设计 JSON

按以下顺序生成每个目标轨道的 notes 数组：

1. **先确认时间网格**：按 8 分音符步进遍历所有小节的所有拍
2. **检查节奏吉他密度**：该时间点是否有 08 的音符？
   - 有 → solo 轨跳过，和声/pad 正常
   - 无 → solo 轨可以在这个时间点说话
3. **生成音符**：按 3.1~3.4 的策略填充
4. **验证**：每小节 4/4 拍，音符不跨拍溢出，力度在范围内

### Step 5: 同步更新 MD

MD 文件必须反映新的设计：
- 更新"段落参与"表
- 更新 status 为"定稿（根据08节奏吉他重新设计）"
- 保留"和弦进行"表和和弦音参考（这些不变）
- 更新"设计说明"为本次重新设计的策略

### Step 6: 生成器脚本（可选）

如果轨道数据量大（>50 音符），建议用 Python 生成器脚本批量生成 JSON，避免手写出错。脚本写在 `.cache/gen_{轨道名}.py`，风格参考之前的 `.cache/gen_solo_05.py`。

生成器要点：
- `beat_pos` 计算：`f"{小节}.{拍}.{子拍}"`（都是 1-based，非浮点避免精度问题）
- `midi` 值：Eb3=51, G3=55, Bb3=58, Eb4=63, F4=65, G4=67, Ab4=68, Bb4=70
- `velocity`：dynamics 映射 + 随机 ±3 人感
- `duration`：用中文全称 "全"/"2分"/"4分"/"8分"/"16分"/"32分"

## 输出

操作完成后，应更新以下文件：
1. 各目标轨道的 `.json` — 新 notes 数组
2. 各目标轨道的 `.md` — 更新设计说明 + 段落表
3. 可选：生成器脚本 `.cache/gen_{轨道名}.py`

## 验证检查清单

- [ ] 每轨 JSON 的 schema/track_id/name 字段正确
- [ ] notes 不为空（即使是"极简点缀"的轨道也应有音符）
- [ ] beat_pos 格式正确（三段 1-based）
- [ ] midi 值在乐器音域内
- [ ] duration 是有效的时值字符串

- [ ] 节奏吉他基础A段落中 solo 轨音符总量 ≤ 该轨非基础A段落的 30%
